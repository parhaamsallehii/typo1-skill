# Component composition — the primary SaaS skill principle

Treat every user's reference as a source of **separable tools**, even when its
appeal comes from their synchronized combination. Preserve a detailed recipe for
the complete sequence and a detailed recipe for each part. Do not make a sequence
mandatory or erase its individual parts into one opaque preset.

## Select and compose

1. Read the actual narration and identify its concept/action/result.
2. Select only useful components: background, icon material, pointer travel,
   anticipation, hover/press, particle accent, reveal, camera move, typography.
3. Assign each a target, start/trigger, local duration, geometry, palette source,
   parent/camera, overlap, entrance/exit and blur participation.
4. Link events only when needed: optional pointer impact can trigger optional
   pixels and optional disc expansion. A reveal may instead trigger on a spoken
   result word, with no mouse, click or app icon.
5. Retarget positions and durations to the actual pane and spoken cue. Preserve
   the component's characteristic acceleration/settle, deformability and materials.
6. Review the combined result for collisions, contradictory cameras, text
   readability and excessive stacked embellishment. Creative freedom means
   motivated choices, not random effects on every beat.

| Component | Inputs / independent trigger | Output / optional event |
| --- | --- | --- |
| Dimensional icon material | Subject-specific artwork and tile geometry | Beveled/raised icon appearance, usable in dock or elsewhere |
| Dock entrance | Group, direction, start, duration, curve | Group arrival; no mouse dependency |
| Cursor trajectory | Path/rotation/target, time map | Hover encounters or optional arrival event |
| Local hover | Target and pointer proximity/cue | Mild magnification/lift; no click/reveal dependency |
| Elastic pre-click anticipation | Cursor mesh, target, preparation and strike intervals | Draw-back/foreshortening/right-tip stretch, then impact cue |
| Hollow pixel burst | Origin, color, start, spread, lifetime | Sparse outlined grid squares/corners; no mouse/disc dependency |
| Five-disc gradient reveal | Origin, palette, start, radius envelope, destination | Five filled alternating-gradient discs, fine rim light, scene coverage |
| Fine rim light / light sweep | Circular perimeter/radius, origin, time, arc and intensity | Narrow moving edge highlight; no filled discs, icon or click required |
| Dimensional symbol | Transparent face, depth treatment, pose/time | Raised white or brand-appropriate symbol; no required circle or click |

## Palette binding

Resolve palette for **each shot/component**, using this precedence:

1. Explicit prompt instruction for this scene/component.
2. For an icon-linked transition, the clicked icon's defining color, unless the
   user requested another brand color.
3. For a standalone transition, the video's supplied organizational palette.
4. If a palette is genuinely unavailable, use a compatible documented reference
   choice and state the assumption. Do not silently replace a client's brand with
   an unrelated remembered brand or the example's red.

Derive light/dark stops from the selected hue while preserving saturation and
contrast; reverse stop order for alternating discs. Bind hollow square strokes
and rim tint to the same family. Keep white specular highlights narrow. Recoloring
must not change the five-disc geometry, material identity or characteristic motion.

## Optional connections and examples

- App demonstration: dock arrival → hover → anticipation → impact; let impact
  trigger hollow pixels slightly before the discs open. Retain the app symbol as
  the new scene's identity. This reproduces the linked source logic.
- Brand reveal: use the five-disc transition in the video's teal with no pointer
  or dock; reveal a supplied result or brand subject at the center.
- Single control click: use elastic anticipation and the target's own state change;
  omit circles/particles when the scene needs calm readability.
- Another transition: use only sparse hollow pixels at a handoff; do not insert
  a red app identity or require a click.

Keep independent start times and local parents in code/native AE. Use event names
such as `impact_time` only as optional orchestration inputs, never a hidden global
dependency. Separate cursor mesh deformation from its screen translation/rotation;
separate scene camera from disc radius; separate icon material from hover/press.
No two animations may fight for the same transform property without nested groups
or an explicit additive composition rule. Clip lower-scene components to the pane.

## Reference and acceptance discipline

Store unchanged uploaded references, user numbers, measured transforms, inferred
values and renderable tests. Keep exact user approvals tied to the actual video
bytes/hash. Both the3.4s dock and2.4s click/reveal studies are now explicitly
approved. Future changed studies do not inherit that approval. Every teaching update must include a new video strictly
under5s. Store each lesson in full detail but load only relevant detailed recipes
for execution. Preserve future alternatives without turning one into a universal
background, color, ease, animation or mandatory component bundle.
